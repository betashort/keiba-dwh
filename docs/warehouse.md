# 倉庫データベース

- 状態: ドラフト
- 日付: 2026-10-24
- 関連: [requirements.md](requirements.md)、[architecture.md](architecture.md)

## 1. 決定

解釈済みの JV-Data を置く倉庫データベースは PostgreSQL とする。ライセンスは PostgreSQL License。

収集アプリの正本は、追記の raw と台帳 SQLite のままである。PostgreSQL へ書くのは、別プロセスの倉庫ローダだけである。収集アプリは接続文字列、スキーマ、テーブルを知らない。

## 2. 役割

| 置き場 | 中身 | 書くプロセス |
| --- | --- | --- |
| `DataRoot/raw` | `JVRead` / `JVGets` のバイト列 | 収集アプリ |
| `DataRoot/state/ledger.sqlite` | 水位、実行履歴、raw の索引、`0B14` の世代 | 収集アプリ |
| PostgreSQL | 推奨キーで揃えた解釈済みの行。特別登録馬、マスタ、レース成績などを含む | 倉庫ローダ |

ローダが読んでよいのは、完了フラグの付いた raw と、それを指す索引だけである。項目の解釈、データ作成年月日による版の採用、倉庫への投入はローダの責務とする。生バイトの正本は raw に残し、PostgreSQL は解釈後の行を持つ。

## 3. 配置

PostgreSQL は、収集アプリと同じ契約者の PC で動かす。ローダは収集アプリのプロセスには入れない。

接続のホスト、ポート、データベース名、認証はローダ側の設定に置く。収集アプリの `config.json` には置かない。

メジャー版は導入時の安定版とし、この文書では番号を固定しない。C# のローダからの接続には Npgsql を使う。

## 4. ほかの候補

倉庫の正本にはしなかったもの。

| 候補 | 扱い |
| --- | --- |
| SQLite | 収集の台帳として使う。倉庫は、ローダの書き込みと分析の参照を同時に行う PostgreSQL にした |
| DuckDB | 単一プロセスの分析エンジン。倉庫の正本にはしない |
| MongoDB | 特別登録馬の名簿は文書にも載る。馬マスタや成績との結合を中心にするため、関係データベースの PostgreSQL にした。ライセンスは SSPL であり、この倉庫の採用ライセンスにはしない |
